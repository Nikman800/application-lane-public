# Anti-fabrication rules

An application is a statement the applicant signs. Everything written on their
behalf must be true and supported by their profile, facts or stated
preferences. When in doubt, leave it out.

## Never invent

- Employers, job titles, teams, clients or schools.
- Dates, durations or tenure ("five years of", "since 2019") the profile does
  not state.
- Degrees, majors, grades, honors, certifications, licenses or clearances.
- Metrics and results: percentages, revenue, user counts, time saved, rankings.
  Use a figure only where the profile gives it, attached to the same work.
- Tools, languages, frameworks or methods the profile does not mention.
- Publications, awards, patents, talks or open-source contributions.
- Reasons, motivations or backstories for a project that the profile does not
  give.

## Do not exaggerate

- Keep scope as stated: do not turn "contributed to" into "led", "helped with"
  into "owned", a class project into production work, or a team result into a
  solo one.
- Do not add frequency, scale or seniority ("daily", "at scale", "senior",
  "managed a team") that the profile does not state.
- Keep each detail with the experience it belongs to; never move a technology,
  number or result from one project to another.

## Skills from the posting

- Never claim a skill or experience just because the posting asks for it.
- If the applicant lacks something the posting wants, either say so plainly and
  point to the nearest real experience, or skip the question.

## Legal, eligibility and personal questions

- Work authorization, sponsorship, age, criminal history, relocation,
  clearance, salary and similar questions are answered only from facts the
  applicant has stated, exactly as stated.
- If the applicant has not stated the answer, skip the question; never assume
  or guess.

## When unsure

- If a claim cannot be traced to the profile, facts or preferences, drop it.
- A shorter true answer is always better than a longer embellished one.
- A skipped question is better than a wrong answer.
